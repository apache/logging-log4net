[#patterns]
= Conversion Patterns

A conversion pattern of xref:manual/configuration/layouts.adoc#patternlayout[`PatternLayout`] is literal text with conversion specifiers.
Each specifier starts with `%`, followed by optional <<format-modifiers,format modifiers>> and a pattern name, e.g. `%-5level`.
There is no separator between a specifier and the text after it.

For example, with the pattern `%-5level [%thread]: %message%newline`

[source,csharp]
----
ILog log = LogManager.GetLogger(typeof(TestApp));
log.Debug("Message 1");
log.Warn("Message 2");
----

writes

[source,text]
----
DEBUG [main]: Message 1
WARN  [main]: Message 2
----

`%-5level` writes the level left justified to five characters.
A more detailed pattern is `%timestamp [%thread] %level %logger %ndc - %message%newline`.

[#pattern-names]
== Pattern names

Single letter aliases are deprecated in favor of the long names.

[cols="1,1,1,4a"]
|===
|Name |Aliases |Supported |Effect

|`appdomain`
|`a`
|all
|The friendly name of the AppDomain where the event was logged.

|`aspnet-cache`
|
|.NET 4.x
|Items of the application cache; see <<aspnet-patterns>>.

|`aspnet-context`
|
|.NET 4.x
|Items of the current `HttpContext`; see <<aspnet-patterns>>.

|`aspnet-request`
|
|.NET 4.x
|Parameters of the current request; see <<aspnet-patterns>>.

|`aspnet-session`
|
|.NET 4.x
|Items of the current session; see <<aspnet-patterns>>.

|`date`
|`d`
|all
|The date of the event in the local time zone; `%utcdate` gives universal time.
May be followed by a date format in braces, e.g. `+%date{HH:mm:ss,fff}+` or `+%date{dd MMM yyyy HH:mm:ss,fff}+`, using the syntax of `DateTime.ToString(string)`.
Without a format ISO8601 is used.

`+%date{ABSOLUTE}+`, `+%date{DATE}+` and `+%date{ISO8601}+` select the log4net date formatters, which are much faster than `DateTime.ToString(string)`.

|`exception`
|
|all
|The exception passed with the message, followed by a newline.
Without an exception nothing is written, not even the newline.
Usually put last, after a `%newline`.

|`file`
|`F`
|all
|The file name where the event was logged.
Slow, see <<caller-location>>.

|`identity`
|`u`
|all
|The name of the current user (`Principal.Identity.Name`).
Slow.

|`level`
|`p`
|all
|The level of the event.

|`line`
|`L`
|all
|The line number where the event was logged.
Slow, see <<caller-location>>.

|`location`
|`l`
|all
|The caller's location: usually the fully qualified method name, followed by the source file name and line number in parentheses.
Very slow, see <<caller-location>>.

|`logger`
|`c`
|all
|The logger of the event.
May be followed by a precision in braces: only that many right most components of the name are written, e.g. `+%logger{2}+` gives `b.c` for `a.b.c`.

|`mdc`
|`X`
|all
|Kept for compatibility, same as `property`; MDC is the old name of `ThreadContext.Properties`.

|`message`
|`m`
|all
|The message supplied by the application.

|`method`
|`M`
|all
|The method name where the event was logged.
Slow, see <<caller-location>>.

|`ndc`
|`x`
|all
|The NDC (nested diagnostic context) of the thread that logged the event.

|`newline`
|`n`
|all
|The platform's line separator; as fast as a literal `\n` or `\r\n`, and portable.

|`property`
|`P`, `properties`
|all
|An event property, with the key in braces, e.g. `+%property{user}+`; without a key all keys and values as a comma separated list.
By default `log4net:HostName` holds the name of the machine that logged the event.
Once an `%aspnet-context`, `%aspnet-request` or `%aspnet-session` pattern is used, `log4net:AspNetRequest` shows up with an empty value.

Properties are searched in this order:

. the event's own `LoggingEvent.Properties`
. `LogicalThreadContext.Properties` of the logging flow
. `ThreadContext.Properties` of the logging thread
. `GlobalContext.Properties`

|`stacktrace`
|
|all
|The stack trace of the event, as `type3.MethodCall3 > type2.MethodCall2 > type1.MethodCall1`.
The number of levels may follow in braces, e.g. `+%stacktrace{3}+`; the default is 1.

|`stacktracedetail`
|
|all
|Like `stacktrace`, with parameter types: `type3.MethodCall3(type param,...) > type2.MethodCall2(type param,...)`.

|`thread`
|`t`
|all
|The name of the thread that logged the event, or its number if it has no name.

|`timestamp`
|`r`
|all
|The milliseconds from the start of the application to the creation of the event.

|`type`
|`C`, `class`
|all
|The fully qualified type name of the caller.
May be followed by a precision in braces, e.g. `+%type{1}+` gives `PatternLayout` for `log4net.Layout.PatternLayout`.
Slow, see <<caller-location>>.

|`username`
|`w`
|all
|The `WindowsIdentity` of the current user.
Slow on the first event of each user; the name is cached per identity.

In classic ASP.NET with `<identity impersonate="true"/>` this is the Windows account the request runs as; `identity` is cheaper and usually what is wanted, the authenticated application user.
On ASP.NET Core there is no impersonation by default, so this is the application pool identity, not the request user.

|`utcdate`
|`utcDate`, `UtcDate`
|all
|Like `date`, in universal time.

|`%`
|
|all
|`%%` writes a single percent sign.
|===

Further converters can be added to a `PatternLayout` with `AddConverter`.

[#format-modifiers]
== Format modifiers

By default a value is written as is.
Between `%` and the pattern name, format modifiers set the width and justification:

* `-` left justifies, padding on the right; the default pads on the left.
* A number sets the minimum width; shorter values are padded with spaces, longer ones are not cut.
* `.` and a number set the maximum width; longer values lose characters at the *beginning*, unlike `printf` in C.
A surrogate pair is never split, so the result can be one character shorter.

[cols="1,1,1,1,3"]
|===
|Modifier |Left justify |Minimum |Maximum |Effect

|`%20logger` |no |20 |none |Pads on the left below 20 characters.
|`%-20logger` |yes |20 |none |Pads on the right below 20 characters.
|`%.30logger` |n/a |none |30 |Cuts from the beginning above 30 characters.
|`%20.30logger` |no |20 |30 |Pads on the left below 20, cuts from the beginning above 30 characters.
|`%-20.30logger` |yes |20 |30 |Pads on the right below 20, cuts from the beginning above 30 characters.
|===

For example, `%-6timestamp [%15.15thread] %-5level %30.30logger %ndc - %message%newline` pads the timestamp to 6 digits on the right, fits the thread name into 15 characters and the logger name into 30.

[#caller-location]
== Caller location

`%type`, `%file`, `%line`, `%method` and `%location` and their aliases read the caller from a `System.Diagnostics.StackTrace`.
This is slow, so use them only where speed does not matter.

In a Release build the stack trace has no debug symbols and may miss calls removed by optimization, so this information can be incomplete or missing.

[#aspnet-patterns]
== ASP.NET patterns

Without a key each shows all items, with `+{key}+` the named one.

`%aspnet-request` shows form fields only once the application has read the request body in classic or buffered mode.
Before that, and after a bufferless read, they are left out, so that a client withholding its body cannot hold the appender.
Query string, cookies and server variables are always shown.

`%aspnet-cache` shows `NOT AVAILABLE` when rendered outside a request.
`%aspnet-context`, `%aspnet-request` and `%aspnet-session` show `NOT AVAILABLE` for an event buffered in another request, logged outside one, or built from `LoggingEventData`.
A buffer only knows the logging request when its `fix` includes `Properties`, as `All` (the default) and `Partial` do; otherwise it shows the request that flushes it.
For the logging request's values use `ThreadContext.Properties` and `%property`.
