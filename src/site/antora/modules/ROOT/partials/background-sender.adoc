Sending happens on a background thread, so a slow or unresponsive {sender-sink} does not hold up
logging. Up to `sendQueueSize` {sender-items} wait in a queue. When it is full, a logging call waits
up to `enqueueTimeoutMillis` for room and discards its {sender-item} if none frees up. After such a
timeout, later calls discard without waiting until a send succeeds; `0` never waits. Discarded
{sender-items} are counted: the first is reported to the error handler at once, the total when the
appender closes. `Flush` waits for the queue to drain; {sender-items} still queued are lost if the
process is killed.
